# SP12: `getEvents` filtered by contract id with a working cursor

**Result: PASS** (testnet RPC https://soroban-testnet.stellar.org, 2026-10-25 ~15:50 WET).

Script: `contracts/spikes/sp12/get-events.ts` (`NODE_OPTIONS=--dns-result-order=ipv4first npx tsx contracts/spikes/sp12/get-events.ts [contractId] [lookbackLedgers]`). Track B's indexer can copy `pageEvents` as is.

## Request shape (@stellar/stellar-sdk 17.4.0 `rpc.Server.getEvents`)

```ts
// first page
server.getEvents({ filters: [{ type: 'contract', contractIds: [contractId] }], startLedger, limit: 10 });
// next pages: cursor from the previous response, no startLedger
server.getEvents({ filters: [{ type: 'contract', contractIds: [contractId] }], cursor, limit: 10 });
```
`startLedger` must be `>= getHealth().oldestLedger` (the script clamps it). Passing both `startLedger` and `cursor` is rejected by the RPC.

## Observations

- Retention: `oldestLedger 5262282`, `latestLedger 5383241` = 120,959 ledgers (about 7 days). The database stays the archive (PLAN 8.3).
- Cursor format: `"0023120844041486335-4294967295"` = `<toid>-<event index>`; event ids look like `"0023120328645427200-0000000000"`. The response `cursor` points past the last event of the page; polling again from the final cursor returns 0 events and a new, advanced cursor (the RPC moves it to the latest ledger), so the indexer can store `cursor` after every poll, including empty ones.
